## 1. 概要

社内利用のロゴ画像編集向けデスクトップアプリケーション。ラスター画像（PNG/JPEG/WebP/BMP）を読み込み、ブラシ・バケツ・色選択・透過化等の編集を行い、ラスター形式または Layered SVG として書き出す。

---

## 2. 目的・背景

- ロゴ画像の色違いバリエーション作成、背景透過処理、軽微な編集を社内で手軽に行えるツールがない
- 汎用画像編集ソフト（Photoshop 等）はライセンス・学習コストが高く、用途過剰
- 「ロゴ色変更」に焦点を絞った軽量ツールを内製することで、用途特化の操作効率とコスト削減を両立する

---

## 3. 用語定義

| 用語 | 定義 |
|------|------|
| マジックワンド | クリックした地点と同色域を許容差で自動選択する機能 |
| マスクペイント | 選択範囲を筆で塗り広げ／消去できる機能 |
| バケツ塗り（Flood Fill） | クリックした地点から連結する同色領域を別色で塗りつぶす機能 |
| Layered SVG | 背景画像を `<image>` タグでラスター埋め込みし、編集レイヤーをパスとして保持する SVG 形式 |
| タイル | キャンバスを 256×256 ピクセル単位に分割した描画・メモリ管理単位 |

### 4.1 MVP（Phase 1 / 初回リリース）

| # | 機能 | 詳細 |
|---|------|------|
| F1 | 画像読込 | ドラッグ&ドロップ + ファイル選択ダイアログ。対応形式: PNG / JPEG / WebP / BMP |
| F2 | ブラシ描画 | サイズ・不透明度可変 |
| F3 | バケツ塗り | 許容差スライダ付き Flood Fill。WASM 実装 |
| F4 | 色選択（カラーピッカー） | HSV / RGB / 16進入力 + スポイト + 最近使った色 8 個 |

| F6 | マスクペイント | 筆で選択範囲を塗り広げ／消去 |
| F7 | 透過化 | 選択範囲を Delete キーでアルファ抜き |
| F8 | レイヤー | 2層固定（背景レイヤー + 編集レイヤー、元画像保護） |
| F9 | Undo/Redo | 履歴上限 30 ステップ（dirty tile + ピクセル差分パッチ方式） |
| F10 | ズーム・パン | マウスホイール / Space+ドラッグ / Ctrl+0 でフィット表示 |
| F11 | 透明背景表示 | 市松模様（チェッカーボード）で透明領域を可視化 |
| F12 | 出力 | PNG / JPEG / WebP / Layered SVG |
| F13 | 自動アップデート | Tauri v2 Updater Plugin |
| F14 | ショートカットキー | Photoshop 準拠（B=ブラシ / G=バケツ / E=消しゴム / V=移動 / Ctrl+Z=Undo 等） |

### 4.2 Phase 2（次期リリース候補）

- フィルタ追加（明度・彩度・色相）
- 筆圧対応 / ペンタブレット対応
- 複数レイヤー対応（最大10枚）

### 4.3 Phase 3（将来構想）

- ベクタトレース付き SVG 出力（vtracer 等）
- 複数ドキュメント同時編集（タブ）
- カラーパレット保存・共有

### 4.4 スコープ外

- AI 自動背景除去（rembg 等の機械学習ベース処理）
- リアルタイム共同編集
- PSD 互換
- 印刷出力
- クラウド連携
- macOS / Linux 対応

## 5. 機能要件詳細

### 5.1 画像読込（F1）
- 起動直後に空キャンバスを表示し、画像未読込状態でも UI 操作可能
- DnD はウィンドウ全体で受け付ける
- 同時に開ける画像は 1 枚（タブ機能なし）
- 読込後はキャンバスサイズ = 画像サイズで固定（リサイズ不可）

### 5.2 ブラシ・バケツ・色選択（F2-F4）
- ブラシは円形固定（特殊ブラシは Phase 2 以降）
- バケツの許容差スライダは 0-255 の整数値
- カラーピッカーは右側プロパティパネルに常設

### 5.3 選択・透過化（F5-F7）
- マジックワンド / マスクペイントは互いに加算・減算で組み合わせ可能
- Shift で選択追加、Alt で選択減算
- 選択中に Delete キーで透過化（αチャンネル 0 に設定）

### 5.4 レイヤー（F8）
- 背景レイヤー: 読み込んだ元画像。編集ロック
- 編集レイヤー: 描画・塗り・選択範囲操作の対象
- レイヤーパネルでの可視性切替・不透明度調整は MVP 範囲

### 5.5 Undo/Redo（F9）
- 履歴は dirty tile（変更があった 256×256 タイル）の前後ピクセル差分として保持
- 30 ステップ超過時は古い履歴を自動破棄
- ファイル読込・新規キャンバス操作は履歴をクリア

### 5.6 出力（F12）
- ラスター出力時はキャンバスを合成してファイル出力
- Layered SVG 出力時の構造:
  ```xml
  <svg>
    <image href="data:image/png;base64,..." />  <!-- 背景レイヤー -->
    <g id="edit-layer">
      <path fill="#FF0" d="..." />  <!-- 編集レイヤーの塗り範囲をパスに変換 -->
    </g>
  </svg>
  ```
- 背景はラスター埋め込み（base64 data URL）、編集レイヤーは色域ごとにパスに変換

### 5.7 自動アップデート（F13）
- 起動時にバックグラウンドで更新確認
- 新バージョンがある場合はユーザーに通知し、同意を得てダウンロード・再起動

## 6. 非機能要件

### 6.1 ターゲット環境

| 項目 | Min（動作保証） | Recommended |
|------|-----------------|-------------|
| CPU | Intel Core i3-8th / AMD Ryzen 3 3200G（4コア 2.0GHz） | Intel Core i5-10th / AMD Ryzen 5 5600U 以上 |
| メモリ | 4GB RAM | 8GB RAM |
| ストレージ | HDD 5400rpm | SSD（NVMe/SATA） |
| GPU | Intel UHD 620 / AMD Vega 8（統合GPU） | 同左 / 外付け（WebGL 2.0 必須） |
| OS | Windows 10 22H2 64bit | Windows 11 64bit |
| 画面解像度 | 1366×768 | 1920×1080 以上 |
| ネットワーク | 初回インストール・自動アップデート時のみ | 同左 |

### 6.2 性能予算

| 指標 | 目標値 | 備考 |
|------|--------|------|
| 起動時間（コールド） | ≤ 3.0 秒 | Min 機・HDD 想定 |
| 起動時間（ウォーム） | ≤ 1.0 秒 | OS キャッシュ前提 |
| 画像読込（FHD 1920×1080） | ≤ 1.0 秒 | |
| 画像読込（4K 3840×2160） | ≤ 3.0 秒 | |
| ブラシ描画レイテンシ | ≤ 16ms（60fps） | mouse → 画面反映 |
| Flood Fill（FHD） | ≤ 200ms | WASM 実装前提 |
| Flood Fill（4K） | ≤ 600ms | |
| マジックワンド（FHD） | ≤ 300ms | |
| Layered SVG 出力（FHD） | ≤ 2.0 秒 | |
| メモリ消費（通常使用） | ≤ 512MB | |
| メモリ消費（ピーク） | ≤ 1.0GB | Undo 履歴込み |
| CPU 使用率（アイドル時） | ≤ 5% | |
| CPU 使用率（操作中・Min機） | ≤ 60% | 熱・バッテリー配慮 |

数値は実装後の実機計測により検証・更新する。

### 6.3 入力画像サポート上限

| 項目 | 上限 |
|------|------|
| 長辺ピクセル | 8,192px |
| 面積上限 | 4,096 × 4,096（16MP） |
| ファイルサイズ | 50MB（圧縮後） |

上限超過時は読込前にエラーダイアログを表示して中止する。

### 6.4 リソース制限

| 項目 | 値 |
|------|---|
| Undo 履歴ステップ | 30（差分パッチ保存） |
| レイヤー枚数 | MVP 2 層固定 / Phase 2 で最大 10 枚 |
| 同時ドキュメント | 1 個固定 |
| WASM ヒープ上限 | 256MB |

### 6.5 バンドル・配布

| 項目 | 目標 |
|------|------|
| インストーラ（Windows .msi） | ≤ 15MB |
| インストール後ディスク使用量 | ≤ 60MB |
| 自動アップデート差分 | ≤ 5MB |

### 6.6 可用性・信頼性

- クラッシュ時の編集中データ自動保存（オートセーブ 5 分間隔、Phase 2 候補）
- 自動アップデート失敗時のフォールバック（旧バージョン維持）

### 6.7 セキュリティ

- 自動アップデートは Ed25519 署名による配信物検証必須
- 署名検証失敗時はインストール拒否
- ダウングレード攻撃を防止: クライアント側で取得バージョン ≤ インストール済みバージョンの場合は更新を拒否し WARN ログ記録
- 配信パスは public だがクライアントに秘匿情報（PAT 等）を一切埋め込まない
- 画像デコーダはマジックバイト検証を行い拡張子偽装を拒否
- Tauri Content Security Policy / capabilities による Rust 側 API 最小権限化を実施
- 依存クレートの既知脆弱性検知（`cargo audit`）を CI で恒久実施

## 7. 技術スタック

### 7.1 確定スタック

| レイヤー | 採用技術 |
|----------|---------|
| デスクトップフレームワーク | Tauri v2 |
| フロントエンド言語 | TypeScript |
| UI フレームワーク | React 18 |
| 状態管理 | Zustand |
| Canvas ライブラリ | Konva.js（レイヤー・選択UI） + 生 Canvas API（ピクセル操作） |
| Worker 通信 | comlink |
| バックエンド言語 | Rust |
| 画像処理 | image / imageproc クレート |
| 並列処理 | rayon |
| 圧縮 | lz4_flex（タイル退避用） |
| 一時ファイル | tempfile |
| WASM ブリッジ | wasm-bindgen + wasm-pack |
| ビルドツール | Vite |
| 自動アップデート | tauri-plugin-updater |

### 7.2 採用しない技術

| 技術 | 不採用理由 |
|------|-----------|
| Electron | バンドルサイズ大、リソース消費過多 |
| Fabric.js | バンドル重め。Konva.js + 自前 SVG エクスポートで代替 |
| Paper.js | ベクタ特化でラスター編集に不向き |
| WebGPU | 統合GPU・WebView2 でのサポートが安定せず、Canvas 2D で性能予算を満たせる見込み |
| AI 推論フレームワーク（onnxruntime 等） | スコープ外（AI 背景除去を採用しないため） |

## 8. アーキテクチャ概略

### 8.1 責務分担

```
┌─────────────────────────────────────────┐
│ Frontend (TS / React / Konva)           │
│  - UI 描画                                │
│  - 即時ブラシ描画                          │
│  - レイヤー・選択管理                      │
└────────────┬──────────────────┬─────────┘
             │ IPC              │ comlink
             ▼                  ▼
┌────────────────────┐ ┌──────────────────────┐
│ Tauri Core (Rust)  │ │ Web Worker           │
│  - ファイル IO       │ │  - OffscreenCanvas    │
│  - アップデータ       │ │  - WASM 呼び出し       │
│  - OS 連携          │ └─────────┬────────────┘
└──────────┬─────────┘           │ wasm-bindgen
           │                     ▼
           │           ┌──────────────────────┐
           │           │ WASM (Rust)          │
           │           │  - Flood Fill        │
           │           │  - マジックワンド      │
           │           │  - ピクセル演算        │
           │           └──────────────────────┘
           ▼
┌────────────────────┐
│ Disk                │
│  - LZ4 タイルスワップ │
│  - 一時ファイル       │
└────────────────────┘
```

### 8.2 設計原則

- **タイル化**: キャンバスを 256×256 タイル単位で管理。可視タイルのみメモリ常駐、非可視タイルは LZ4 圧縮でディスク退避
- **差分 Undo**: 全画面スナップショットは不採用。dirty tile のピクセル差分パッチを保持
- **WASM 境界**: 1メガピクセル超または全画面処理（Flood Fill / マジックワンド）は WASM。局所処理（ブラシストローク）は JS Canvas
- **OffscreenCanvas + Worker**: 重描画は Worker に逃がして UI スレッドのブロックを回避
- **GPU 方針**: Canvas 2D を基本とし、必要時のみ WebGL を限定使用

## 9. 外部 I/F・運用

### 9.1 自動アップデート

| 項目 | 内容 |
|------|------|
| プラグイン | tauri-plugin-updater |
| ソースリポジトリ | GitHub private リポジトリ（`<org>/choco`、社内 Organization 配下） |
| 配信リポジトリ | GitHub public リポジトリ（`<org>/choco-releases`、配信物のみ） |
| 配信物 | `.msi`, `.msi.sig`, `latest.json` のみ。ソースコード・Issue・PR は private 側に維持 |
| 配信物の真正性担保 | Ed25519 署名のみ（クライアントに秘匿情報を一切埋め込まない） |
| 署名方式 | Ed25519 |
| 秘密鍵保管 | private 側 GitHub Actions Secrets（CI で自動署名） |
| 配信形式 | 差分アップデート対応（フル配信フォールバック可） |
| 更新確認タイミング | 起動時バックグラウンド |
| ダウングレード防御 | クライアント側で「取得バージョン ≤ インストール済みバージョン」を semver 比較して拒否、WARN ログ記録 |

### 9.2 ログ・モニタリング

- 開発ビルドにのみ FPS / メモリオーバーレイを実装
- Rust 側の重処理は criterion ベンチを CI 化
- Tauri `app::setup` フックで起動時間を計測

## 10. 受入基準（MVP 完成条件）

- [ ] Min 仕様 PC（RAM 4GB / Core i3-8th 相当）でコールド起動 3 秒以内
- [ ] FHD 画像でブラシ操作が 60fps を維持
- [ ] FHD 画像で Flood Fill 200ms 以内、マジックワンド 300ms 以内
- [ ] 選択 + Delete でアルファチャンネル保持の透過化が可能
- [ ] PNG / JPEG / WebP / Layered SVG 出力ファイルが一般ビューワー（Windows フォト / ブラウザ）で正しく開ける
- [ ] 自動アップデート動作確認（テスト配信→検知→ダウンロード→再起動の一連が成功）
- [ ] Windows 10 22H2 / Windows 11 で全機能動作
- [ ] インストーラサイズ 15MB 以下
- [ ] 性能予算（§6.2）の全主要指標を実機計測でクリア

---

## 11. 制約・前提

- 利用ユーザーは社内のみ（ライセンス・利用規約は社内規定に準拠）
- GitHub Organization の private ソースリポジトリ（`<org>/choco`）と public 配信リポジトリ（`<org>/choco-releases`）の両方が利用可能であること
- 配信用 GitHub Actions の実行枠を確保していること
- public 配信リポジトリには配信物（`.msi` / `.msi.sig` / `latest.json`）のみを配置し、ソースコード・Issue・PR は含めない
- Ed25519 鍵ペアの初期生成は別途運用手順を定める
